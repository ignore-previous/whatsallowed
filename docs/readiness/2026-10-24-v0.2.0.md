# Readiness assessment: What's Allowed 0.2.0

Written by Claude Fable 5.1 on 24 Oct 2026. I did not build this release and wrote none of its commits. The build and its reviews were done by Claude models (Claude Sonnet 5.5 reviewed the code, Claude Fable 5.1 reviewed the copy), so this is not a cross-family review. Standard followed: the maintainer's readiness checklist and the 0.1.0 assessment in this folder.

**Recommendation: ready with listed follow-ups.** The new summary block does what the README says, the tarball is clean and matches a fresh build, every commit carries the public identity, and the credential masking added in this release works on the cases it names. Two things should be done before `npm publish`: one sentence in `docs/THREAT_MODEL.md` (shipped in the tarball) overstates masking and contradicts the tool's own output and the plugin skill; and a Claude Sonnet 5.5 re-check of the last two commits was still running when I wrote this, so its outcome has to be read first. Neither needs a code change for 0.2.0. Section 7 has the list.

## 5. Credential masking, measured

Fixture: a project whose `.claude/settings.json` sets `ANTHROPIC_BASE_URL` to `https://alice:<pw>@proxy.example.net/v1`, an `ANTHROPIC_AUTH_TOKEN`, an allow rule with a Bearer header, an allow rule `Bash(docker login -u bob -p <pw> *)`, a hook `API_TOKEN="<tok>" /usr/bin/notify --send`, an HTTP hook with `?token=<tok>`, and a `.mcp.json` with `npx -y --token <tok> some-pkg@1.2.3`, a `git+https://user:<pw>@…` package, and a remote server with `?key=<key>` and a Bearer header. All values were fakes. I then searched the text, JSON and SARIF output for each one.

| Value | In the summary block (new in 0.2.0) | In a finding (unchanged since 0.1.0) |
|---|---|---|
| Password in `ANTHROPIC_BASE_URL` | No. ENDPOINT items show the setting name only. | **Yes**: ENDPOINT-001 `match`, in text, JSON and SARIF. |
| `ANTHROPIC_AUTH_TOKEN` value | No. | No: ENDPOINT-002 shows `sk-ant… (126 chars)`. |
| Bearer token in an allow rule | No: `Bash(curl -H 'Authorization: •••' *)`. | Not a finding. |
| `docker login -p <pw>` in an allow rule | **Yes**, in the ALLOW item. `scrub()` has no rule for a bare `-p`. Known open item 2. | Not a finding. |
| Quoted `API_TOKEN="…"` before a hook command | No. HOOK item shows `notify`. | Not a finding. |
| `?token=` on an HTTP hook URL | No. HTTPHOOK items show the host only. | **Yes**: HTTPHOOK-001 `match`. |
| `npx --token <tok> pkg` | **Yes**: the item reads `npx <tok>` because the token is taken as the package name. Known open item 3. | **Yes**: MCP-001 `match` and `fix` ("for example npx <tok>@1.2.3"). |
| Password in a `git+https://user:<pw>@…` package | No: "npx package at github.example.com". | **Yes**: MCP-001 `match` and `fix`, and the SARIF `message.text`. |
| `?key=` on a remote MCP URL | No: host only. | No: MCP-007 shows the host. |
| Bearer header on a remote MCP server | No. | Not a finding. |

So the summary leaks only in the two cases the build team already listed. Every other leak is in a finding's `match` or `fix`, which 0.2.0 did not touch. The baseline file held none of the values.

Direct calls to `scrub()` confirm the stated gaps: `make CC=gcc` becomes `make CC=•••` (over-masking); `mysql -ppw`, `docker login -p pw` and `user:pw@` without a `//` prefix are left as they are. `curl -u bob:pw`, `--token=abc` and `FOO="a b"` are masked.

## 6. Open items

Confirmed from the evidence above. None blocks 0.2.0 in my view; the reasons are given.

1. **Finding `match` and `fix` fields quote settings verbatim.** ENDPOINT-001, HTTPHOOK-001 and MCP-001 showed a password or token in text, JSON and SARIF. The `fix` field of MCP-001 repeats it, and SARIF puts the fix in `message.text`. Unchanged since 0.1.0, which is already public with the same behaviour. 0.2.0 adds the skill instruction not to repeat these parts. The build team plans to route `match` through `scrub()` in 0.2.1; `fix` needs the same. I would add: the finding's own `why` text for ENDPOINT-001 says "your credentials are sent to this address", so a password in the address is likely in real use.
2. **`scrub()` gaps.** Misses `docker login -p pw` and `mysql -ppw`; over-masks `make CC=gcc`. Confirmed. Only affects the `--verbose` item list and the ALLOW `broadest` field.
3. **`npx --token X pkg` shows X as the package.** Confirmed in the summary item and in the MCP-001 finding and fix. Pre-existing in the finding; new in the summary.
4. **Removed-server note appears twice in text output.** Confirmed: once as `Note: MCP server git in <absolute path> was removed since the baseline.` and once as the DRIFT item `removed: "git"`. The note also prints the project file's absolute path where every other line uses `./.mcp.json`. Both are cosmetic and pre-date 0.2.0.
5. **No CHANGELOG.** The verdict line changed from "settings files" to "files" and the second line on a clean run from "That is good news, but it does not promise your setup is safe." to "The summary at the end shows what was checked." The JSON `notes` array no longer carries "No baseline recorded, so MCP drift wasn't checked…"; the DRIFT summary row carries that information instead. A JSON consumer that matched on that note would notice.
6. **New: `docs/THREAT_MODEL.md` line 39** says findings "never" show a full value and that JSON and SARIF are "safe to upload to CI". Section 5 shows otherwise, and `SKILL.md` line 22 now says the opposite. The file ships in the tarball.
7. **Pending review.** A Claude Sonnet 5.5 re-check of `b3bcc1c` and `8e9aad4` was running when this was written. Its two earlier passes each found a real leak (two in `c0200ad`, two in `fcc3d09`) that were then fixed, so its third result matters.

Still open from 0.1.0 and unchanged: no human has checked any label or rule; real-world figures are precision only; SKILL, DENY, DRIFT and HOOK have no real-world precision data; no macOS or Linux run outside CI.

## 7. Before publishing

1. **Reword `docs/THREAT_MODEL.md` line 39** so it matches the tool and the skill. For example: "Keys and tokens the SECRET and ENDPOINT credential rules find are shown as a prefix and a length, never in full, in text, JSON and SARIF. Other findings quote the setting they matched, which can include a password or token written inside an address or command. Read the output before you paste or upload it." One file, one commit, no code change. Rebuild is not needed because the bundle does not include the docs.
2. **Read the pending Claude Sonnet 5.5 re-check** of `b3bcc1c` and `8e9aad4`. If it requests changes to `scrub()` or `program()`, fix, rebuild `dist/cli.mjs`, re-run `npm run check` and `npm run prepublish-scan`, and re-check that the committed bundle matches the build.
3. After any further commit: confirm `git log 383b9eb..HEAD` still shows only the `ruddy-dev` noreply identity, and `npm pack --dry-run` still lists 9 files at version 0.2.0.

Recommended for 0.2.1, not blocking: route finding `match` and `fix` through `scrub()` (item 1); teach `scrub()` the bare `-p` and `-p<value>` forms and leave `NAME=value` alone when the name is not credential-like (item 2); make `findRunner` skip `--flag value` pairs before taking the package name (item 3); drop the duplicate removed-server note or make its path relative (item 4); add a short CHANGELOG that records the verdict wording, the new `summary` key and the removed JSON note (item 5).

## 9. Addendum by the build lead (Claude Opus 5.5), after this assessment

Added after the assessment above was written. It records what changed, not a new verdict.

- **The pending Claude Sonnet 5.5 re-check** of `b3bcc1c` and `8e9aad4` (section 7, item 2) found the masking fixes correct. It requested one change: some `scrub()` patterns had unbounded repeats, and a long, crafted allow rule or MCP argument could make a scan take minutes. A test with four hostile inputs, each up to 200,000 characters, timed out on the old code. The fix cuts rule text to 300 characters before masking and bounds every repeat, and the test now passes. A quoted value cut off at the limit is still masked.
- **`docs/THREAT_MODEL.md` line 39** (section 7, item 1) now says which findings are masked, and that other findings can quote a password or token written inside an address or command.
- **Sonnet's check of that fix:** approved, no blockers. Eleven hostile inputs up to 200,000 characters ran in under 2 ms each, and no secret leaked when it straddled the cut, with one exception. A web-address password cut off before its `@` kept its first characters. A further one-line change masks an address cut off that way, and a test covers every cut position.
- **After these changes:** `npm run check` passed (344 tests, eval figures unchanged), `npm run prepublish-scan` passed (393 files clean), and the bundle's first line is unchanged.
